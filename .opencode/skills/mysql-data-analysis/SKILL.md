# MySQL 数据统计与分析工作流

当用户提出数据统计、报表查询或指标分析需求时，请严格按照以下步骤执行：

## 1. 明确分析目标与指标定义
- 确认核心统计指标（如：UV、PV、转化率、留存率、GMV、ROAS 或自定义业务指标）。
- 明确时间维度（如：按天、小时、周、月聚合）及筛选过滤条件。

## 2. 设计与编写高效 SQL
- **聚合与窗口函数**：优先使用聚合函数（`SUM`, `COUNT`, `AVG`）及窗口函数（`ROW_NUMBER()`, `SUM() OVER(PARTITION BY...)`）来处理分组统计。
- **性能防范**：
  - 避免在 `WHERE` 子句中对索引字段使用函数或计算，确保能够命中索引。
  - 针对大表统计，建议采用“先过滤、后聚合”或“分步临时表/子查询”策略。
  - 涉及大范围扫描时，评估是否需要利用时间字段走索引范围查询。
- **代码规范**：SQL 关键字大写，表名和字段名保持清晰，复杂逻辑配合适当的注释。

## 3. 性能评估与执行计划检查
- 引导用户对复杂的统计 SQL 执行 `EXPLAIN`。
- 检查是否存在全表扫描（`type: ALL`）、不合理的临时表（`Using temporary`）或文件排序（`Using filesort`），并给出优化建议。

## 4. 输出格式
- 提供清晰、可直接执行的 SQL 语句。
- 简要解释统计逻辑及核心字段的含义。
