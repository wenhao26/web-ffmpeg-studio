# ADR-001: 任务状态用文件型存储（无 Redis/数据库）

- 状态：已接受
- 日期：2026-09

## 背景

任务需要在以下进程间共享：web worker（HTTP 登记/查询）× 2 与 task-worker × 2
（领取/更新进度）。可选方案：Redis、SQL 数据库、文件存储。

## 决策

任务状态一律以 JSON 文件保存在 `backend/storage/tasks/`，跨进程读写通过
原子重命名落盘；队列领取用 `.claim.lock` + `flock` 保证同一任务只被一个
task-worker 领取（`TaskCache` / `TaskWorker`）。

## 理由

- 部署零基础设施：单目录即全部状态，克隆即可运行，符合本地工具定位。
- 任务量级低（个人/小团队手动转码），文件扫描开销可忽略。
- 状态可持久化重启恢复，且人可直接 `cat` 排查。

## 后果

- 正面：无外部依赖、易备份、易解释。
- 负面：不支持多机横向扩展与复杂查询；高并发写需靠 flock 串行化。
- 约束：**禁止**"优化"为内存缓存或引入数据库——除非先修订本 ADR 并经人工确认。
  多机扩展时应新增 ADR 声明取代本决策。
