**1GB 大文件上传注意事项:**
| 层 | 配置项 | 值 |
|----|--------|-----|
| Webman | `upload_max_size` | 1073741824 (1GB) |
| Webman | `post_max_size` / `max_file_size` | ≥ 1GB |
| PHP | `upload_max_filesize` | 1024M |
| PHP | `post_max_size` | 1100M (预留请求头空间) |
| PHP | `max_execution_time` | 不是问题 (上传由 Webman 处理), 但保持宽容 |
| Nginx (若代理) | `client_max_body_size` | 1100m |
| 前端 | 上传进度显示 | XHR 的 upload.onprogress |
| 前端 | 分片策略 | 单次整传, 不做分片 (1GB 内); 预留后续分片接口扩展 |

#### 2.2.3 FFmpeg 执行

```
POST /api/ffmpeg/execute
Content-Type: application/json

请求参数:
  - file_id: string (必填)
  - output_format: string (必填, 白名单: mp4|webm|mkv|mov|hls)
  - video_codec: string (可选, 白名单: libx264|libx265|libvpx-vp9|libaom-av1)
  - audio_codec: string (可选, 白名单: aac|libmp3lame|libopus)
  - crf: int (可选, 范围 0-51, 默认 23)
  - video_bitrate: string (可选, 如 "2M")
  - audio_bitrate: string (可选, 如 "128k")
  - preset: string (可选, 白名单: ultrafast|superfast|veryfast|faster|fast|medium|slow|slower|veryslow)
  - start_time: string (可选, 如 "00:00:10")
  - end_time: string (可选, 如 "00:01:30")
  - crop: string (可选, 如 "1920:1080:0:0")
  - scale: string (可选, 如 "1280:720")
  - watermark_type: string (可选, 白名单: image|text)
  - watermark_text: string (可选, 水印文字)
  - watermark_image: string (可选, 水印图片 file_id)
  - watermark_position: string (可选, 白名单: top-left|top-right|bottom-left|bottom-right|center)
  - custom_args: string (可选, 专家模式自定义参数, 需白名单校验)

响应 (任务仅登记即返回, 执行由 task-worker 异步进行, 见 ADR-002):
{
  "code": 200,
  "message": "任务已登记",
  "data": {
    "task_id": "task-uuid",
    "status": "pending"
  }
}
```

#### 2.2.4 SSE 任务进度推送通道

```
GET /api/ffmpeg/task/{task_id}/stream
Accept: text/event-stream

连接方式:
  前端在 execute 接口返回 task_id 后，立即通过 EventSource 建立 SSE 连接。
  FFmpeg 由 task-worker 进程执行并把进度写入任务 JSON；SSE 通道以 0.3s
  Timer 轮询该 JSON，推送增量日志与变化的进度（见 ADR-004）。

事件流格式 (SSE standard):
  event: progress
  data: {"type":"progress","task_id":"task-uuid","progress":67.5,"speed":"2.5x","eta":"00:00:30"}
  id: 42

  event: log
  data: {"type":"log","task_id":"task-uuid","line":"frame=  205 fps= 30 q=28.0 size=   10240kB time=00:00:06.83 bitrate= 12288.0kbits/s speed= 2x"}

  event: complete
  data: {"type":"complete","task_id":"task-uuid","code":200,"data":{"command":"...","output":"...","file_url":"/storage/outputs/task-uuid/output.mp4","file_size":10240000}}

  event: error
  data: {"type":"error","task_id":"task-uuid","code":500,"message":"FFmpeg execution failed: timeout","data":{"command":"...","exit_code":1}}

  服务端不发送心跳注释行；连接保活依赖传输层/代理配置（见 ADR-004）

SSE 事件类型汇总:
| 事件名   | 触发时机                          | 字段                                       |
|----------|-----------------------------------|--------------------------------------------|
| progress | 任务 JSON 进度值变化时推送 (0.3s 轮询, 值去重) | progress/speed/eta                          |
| log      | 任务 JSON 新增一行 stderr 日志 (增量推送)  | line                                        |
| complete | 任务终态 completed                        | data.command/data.output/data.file_url      |
| error    | 任务终态 failed (超时/退出码非 0)          | code/message/data.command/data.exit_code    |

前端断线重连策略:
  1. EventSource 默认自动重连 (浏览器内置, 指数退避)
  2. 监听 onerror 事件: 若重连 3 次仍失败, 触发 REST 轮询回退
  3. 回退机制: 每 2s 请求 GET /api/ffmpeg/task/{task_id}/status 获取最新快照

服务端实现要点:
  1. Webman 控制器设置响应头:
     Content-Type: text/event-stream
     Cache-Control: no-cache
     Connection: keep-alive
     Transfer-Encoding: chunked (经 Vite/nginx 代理必需, 见 TaskController 注释)
     X-Accel-Buffering: no
  2. 任务完成或失败后向 SSE 推送终态事件并主动断开连接
  3. 客户端断开 (Connection reset) 时仅清理 SSE 定时器, 任务继续后台执行,
     可凭 task_id 重连 /stream 或查询 /status
  4. 进度计算: progress = 已处理时间 / format.duration * 100 (依据 probe 结果)
  5. 进度推送: 0.3s 轮询任务 JSON, 仅在进度值变化时推送, 防止高频刷新
```

#### 2.2.6 任务文件型存储设计 (ADR-001)

```text
FFmpeg 任务执行信息不依赖数据库或 Redis, 采用文件型存储
(backend/storage/tasks/{task_id}.json), 供 web 与 task-worker 进程共享。

存储结构:
{
  "task_id": "task-uuid",
  "file_id": "xxx",
  "command": "ffmpeg ...",
  "status": "pending",            // pending | processing | completed | failed
  "progress": 67.5,
  "speed": "2.5x",
  "eta": "00:00:30",
  "logs": [...],                  // stderr 行 (status 接口回传最近 100 条)
  "output_url": null,
  "output_size": null,
  "error": "",
  "exit_code": null,
  "created_at": 1732838400
}

队列领取:
  - TaskWorker (2 进程) 每 0.5s 扫描 pending 任务;
  - 通过 {task_id}.claim.lock + flock 原子领取, 保证同一任务只执行一次。

生命周期:
  - CleanupService 每小时调用 TaskCache::gc() 回收过期任务 JSON
    (含终态任务的滞留查询期), 详见 STORAGE_POLICY.md。

禁止改回内存缓存 / 引入数据库, 除非先修订 ADR-001 并经人工确认。
```

### 2.3 后端核心服务落地细节

#### 2.3.1 BinaryChecker

```php
职责:
  - 从 config/ffmpeg.php 读取二进制路径
  - 校验 file_exists() + is_executable()
  - 缓存校验结果避免重复检查
  - 校验失败抛出 BinaryNotFoundException

方法签名:
  - checkFfmpeg(): string  // 返回有效路径
  - checkFfprobe(): string // 返回有效路径
  - clearCache(): void
```

#### 2.3.2 InputSanitizer

```php
职责:
  - 枚举型参数白名单校验 (编码器、格式、预设、水印位置/类型)
  - 数值型参数范围校验 (CRF 0-51, 码率正则)
  - 时间格式校验 (HH:MM:SS 或 HH:MM:SS.mmm)
  - crop/scale 几何格式与文本长度上限校验
  - 不做转义: escapeshellarg 属于 CommandBuilder 职责 (安全三段链分工)
  - custom_args 在此仅做长度校验; token 白名单过滤在 CommandBuilder

白名单定义:
  VIDEO_CODECS  = ['libx264', 'libx265', 'libvpx-vp9', 'libaom-av1']
  AUDIO_CODECS  = ['aac', 'libmp3lame', 'libopus']
  FORMATS       = ['mp4', 'webm', 'mkv', 'mov', 'hls']
  PRESETS       = ['ultrafast', 'superfast', 'veryfast', 'faster', 'fast', 'medium', 'slow', 'slower', 'veryslow']
  POSITIONS     = ['top-left', 'top-right', 'bottom-left', 'bottom-right', 'center']
```

#### 2.3.3 CommandBuilder

```php
职责:
  - 接收校验后的参数数组
  - 调用 InputSanitizer 验证
  - 按 FFmpeg 语法规则拼装完整命令
  - 返回命令字符串 (不执行)

方法签名:
  - build(array $params): string

示例输出:
  "ffmpeg -i storage/inputs/xxx.mp4 -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k storage/outputs/xxx/output.mp4"
```

#### 2.3.4 ProcessRunner

```php
职责:
  - 使用 Symfony Process::fromShellCommandline() 执行已转义的完整命令
  - 双超时 (整体 + 空闲, 默认 300s, 来自 config/ffmpeg.php), 超时抛
    ProcessTimeoutException (全局 Handler 映射 504)
  - 捕获 stdout + stderr 全文
  - 按 \r / \n 切分 stderr 行并逐行上抛给 progressCallback;
    time/speed 等字段的语义化解析由消费方 (TaskRunner) 完成

方法签名:
  - execute(string $command, ?callable $progressCallback = null): array

返回数组 (关联数组, 非对象):
  - exit_code: int    // 异常终止为 -1
  - stdout: string
  - stderr: string
  - duration: float   // 执行耗时秒数
```

#### 2.4.2 Pinia Store 设计

```typescript
// media store
interface MediaState {
  fileId: string | null;
  filename: string;
  fileSize: number;
  mimeType: string;
  probeData: ProbeResult | null;
  loading: boolean;
}

// params store
interface ParamsState {
  outputFormat: string;
  videoCodec: string;
  audioCodec: string;
  crf: number;
  videoBitrate: string;
  audioBitrate: string;
  preset: string;
  startTime: string;
  endTime: string;
  crop: string;
  scale: string;
  watermarkType: string;
  watermarkText: string;
  watermarkPosition: string;
  customArgs: string;
  // computed: generateCommand() → 实时 FFmpeg 命令字符串
}

// task store
interface TaskState {
  taskId: string | null;
  status: 'idle' | 'processing' | 'completed' | 'failed';
  progress: number;
  speed: string;
  eta: string;
  logs: string[];
  outputUrl: string | null;
}
```

### 2.5 存储与生命周期

#### 2.5.1 目录结构

```
storage/
├── inputs/              # 用户上传原始文件
│   └── {file_id}.ext
├── outputs/             # 处理完成产物
│   └── {task_id}/
│       ├── output.mp4
│       └── *.ts (HLS 切片)
└── temp/                # 运行时临时文件
    └── {task_id}/
```

#### 2.5.2 清理策略

| 文件类型 | 保留时长 | 清理方式 |
|----------|----------|----------|
| inputs/ | 24 小时 | CleanupService（Workerman Timer 每小时执行，按 filemtime） |
| outputs/ | 72 小时 | 同上 |
| temp/ | 1 小时 | 同上（按 TTL 过期删除，非任务完成即删） |

任务 JSON（`backend/storage/tasks/`）由 `TaskCache::gc()` 随同一 Timer 回收（ADR-001）。
目录运行期自动创建。详见 `STORAGE_POLICY.md`。
