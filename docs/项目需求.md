**1GB 大文件上传注意事项:**
| 层 | 配置项 | 值 |
|----|--------|-----|
| Webman | `upload_max_size` | 1073741824 (1GB) |
| Webman | `post_max_size` / `max_file_size` | ≥ 1GB |
| PHP | `upload_max_filesize` | 1024M |
| PHP | `post_max_size` | 1100M (预留请求头空间) |
| PHP | `max_execution_time` | 不是问题 (上传由 Webman 处理), 但保持宽容 |
| Nginx (若代理) | `client_max_body_size` | 1100m |
| 前端 | 上传进度显示 | XHR 的 upload.onprogress |
| 前端 | 分片策略 | 单次整传, 不做分片 (1GB 内); 预留后续分片接口扩展 |

```

#### 2.2.4 SSE 任务进度推送通道

```
GET /api/ffmpeg/task/{task_id}/stream
Accept: text/event-stream

连接方式:
  前端在 execute 接口返回 task_id 后，立即通过 EventSource 建立 SSE 连接。
  后端在后台启动 FFmpeg 进程，实时解析 stderr 输出并通过 SSE 推送。

事件流格式 (SSE standard):
  event: progress
  data: {"type":"progress","task_id":"task-uuid","progress":67.5,"speed":"2.5x","eta":"00:00:30"}
  id: 42

  event: log
  data: {"type":"log","task_id":"task-uuid","line":"frame=  205 fps= 30 q=28.0 size=   10240kB time=00:00:06.83 bitrate= 12288.0kbits/s speed= 2x"}

  event: complete
  data: {"type":"complete","task_id":"task-uuid","code":200,"data":{"command":"...","output":"...","file_url":"/storage/outputs/task-uuid/output.mp4","file_size":10240000}}

  event: error
  data: {"type":"error","task_id":"task-uuid","code":500,"message":"FFmpeg execution failed: timeout","data":{"command":"..."}}

  连接建立后 30 秒无事件 → 发送心跳注释行 ": keep-alive\n\n"

SSE 事件类型汇总:
| 事件名   | 触发时机                          | 字段                                       |
|----------|-----------------------------------|--------------------------------------------|
| progress | stderr 每解析到一行进度 (节流 500ms)| progress/speed/eta                          |
| log      | stderr 每收到一行原始输出          | line                                        |
| complete | 进程退出码 0                      | data.command/data.output/data.file_url     |
| error    | 进程超时/退出码非 0/校验失败      | code/message/data                           |

前端断线重连策略:
  1. EventSource 默认自动重连 (浏览器内置, 指数退避)
  2. 监听 onerror 事件: 若重连 3 次仍失败, 触发 REST 轮询回退
  3. 回退机制: 每 2s 请求 GET /api/ffmpeg/task/{task_id}/status 获取最新快照

服务端实现要点:
  1. Webman 控制器设置响应头:
     Content-Type: text/event-stream
     Cache-Control: no-cache
     Connection: keep-alive
     X-Accel-Buffering: no
  2. 任务完成或失败后向 SSE 推送终态事件并主动断开连接
  3. 客户端断开 (Connection reset) 时停止 stderr 解析器, 任务继续后台执行
  4. 进度计算: progress = 已处理时间 / format.duration * 100 (依据 probe 结果)
  5. 显示进度节流: 每 500ms 只推送一次 progress, 防止高频刷新
```

#### 2.2.6 任务内存存储设计

```text
FFmpeg 任务执行信息不依赖数据库, 采用服务器内存缓存 (Webman 自带 Cache)。
每个任务一个独立 key: "ffmpeg:task:{task_id}"

存储结构:
{
  "task_id": "task-uuid",
  "file_id": "xxx",
  "command": "ffmpeg ...",
  "status": "processing",            // processing | completed | failed
  "progress": 67.5,
  "speed": "2.5x",
  "eta": "00:00:30",
  "logs": [...],                     // 最近 N 条 stderr 行 (环形缓冲)
  "output_url": null,
  "output_size": null,
  "created_at": 1732838400,
  "expires_at": 1732842000           // created_at + 6h, 防内存泄漏
}
```

内存清理策略:
  - 任务终态 (completed/failed) 后保留 10 分钟供前端查询
  - 超过 expires_at 的 key 由后台定时任务统一清除
```

### 2.3 后端核心服务落地细节

#### 2.3.1 BinaryChecker

```php
职责:
  - 从 config/ffmpeg.php 读取二进制路径
  - 校验 file_exists() + is_executable()
  - 缓存校验结果避免重复检查
  - 校验失败抛出 BinaryNotFoundException

方法签名:
  - checkFfmpeg(): string  // 返回有效路径
  - checkFfprobe(): string // 返回有效路径
  - clearCache(): void
```

#### 2.3.2 InputSanitizer

```php
职责:
  - 枚举型参数白名单校验 (编码器、格式、预设等)
  - 数值型参数范围校验 (CRF 0-51, 码率正则)
  - 时间格式校验 (HH:MM:SS 或 HH:MM:SS.mmm)
  - 字符串参数 escapeshellarg() 转义
  - 自定义参数 (custom_args) 严格白名单过滤

白名单定义:
  VIDEO_CODECS  = ['libx264', 'libx265', 'libvpx-vp9', 'libaom-av1']
  AUDIO_CODECS  = ['aac', 'libmp3lame', 'libopus']
  FORMATS       = ['mp4', 'webm', 'mkv', 'mov', 'hls']
  PRESETS       = ['ultrafast', 'superfast', 'veryfast', 'faster', 'fast', 'medium', 'slow', 'slower', 'veryslow']
  POSITIONS     = ['top-left', 'top-right', 'bottom-left', 'bottom-right', 'center']
```

#### 2.3.3 CommandBuilder

```php
职责:
  - 接收校验后的参数数组
  - 调用 InputSanitizer 验证
  - 按 FFmpeg 语法规则拼装完整命令
  - 返回命令字符串 (不执行)

方法签名:
  - build(array $params): string

示例输出:
  "ffmpeg -i storage/inputs/xxx.mp4 -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k storage/outputs/xxx/output.mp4"
```

#### 2.3.4 ProcessRunner

```php
职责:
  - 使用 Symfony Process 组件执行命令
  - 设置硬性超时 (默认 300s, 可配置)
  - 捕获 stdout + stderr
  - 解析 stderr 中的进度信息 (frame=, fps=, time=, speed=)
  - 返回结构化执行结果

方法签名:
  - execute(string $command, ?callable $progressCallback = null): ProcessResult

进程进度回调 (配合 SSE):
  使用 Symfony Process 的 incrementalOutput() 监听 stderr, 逐行解析:
    frame=205  fps=30  q=28.0  size=10240kB  time=00:00:06.83  bitrate=12288.0kbits/s  speed=2x
  提取字段: time → 进度百分比, speed → 倍速, time/速度 → ETA
  每解析到一行调用 $progressCallback($parsedLine) 供 SSE 推送

ProcessResult 结构:
  - exitCode: int
  - stdout: string
  - stderr: string
  - duration: float (执行耗时秒数)
```

## 三、编码规范与安全基线

### 3.1 PHP 编码规范

#### 3.1.1 强制声明

```php
<?php
declare(strict_types=1);
```

所有 PHP 文件必须在第一行声明严格类型。

#### 3.1.2 PSR-12 风格

- 大括号 `{` 换行放置
- 缩进使用 4 个空格
- 命名空间与 use 声明之间空一行
